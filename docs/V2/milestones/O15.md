# O15 — FILL and CIRCLE to the EXROM: milestone report

**Date:** 2026-10-30. **Status: complete.** `FILL` and `CIRCLE` are rebuilt in the graphics EXROM (service slots 7
and 8; the table grew to 16 slots, ABI 2), with thin HOME stubs. Four defects found during the step are fixed in it.
Branch `v2/step-o15-fill-circle` from master `df391e6` (PR #8 merged at the start of the session). Spec:
`docs/V2/FILL_CIRCLE_SPEC.md` (owner decisions O15-1..9, all as recommended).

- **CIRCLE:** 16-bit signed centre and radius, each point clipped and drawn once (Leap-C's `circle`, with a signed
  loop test: the unsigned one never ends for r = 0); r < 0 draws nothing; direct plot in Normal mode, the slot-0
  veneer in HIRES. About 2.6× faster.
- **FILL:** byte-level span fill on two planes (the screen and a shadow at `+$1B00` in the same layout), one seed
  per run on the rows above and below, a 1,664-entry seed stack and a recovery sweep when a seed is dropped (Leap V2's
  D7, byte-parallel), so a fill is always complete. A seed off the screen, or HIRES, does nothing. 38-66× faster on
  large areas.
- **Defects fixed** (found in this step): HIRES colours were written at `$6000 + y*32 + col`; the SCLD reads a pixel
  byte's 8×1 attribute at the byte's address + `$2000` (ZEsarUX `core_spectrum.c`), so only y = 0, 64, 128 were right.
  PLOT and LINE indexed past the 24-row table for y 192-255; after this step's layout that became a RAM write
  (`$801D`). The 8th nested CATCH frame overlapped `SPACES_COUNT` (a THROW to it restored a wrong SP and hung).
  `LATEST`/`HERE` sat at the bottom of the data stack's range (a 1,100-cell stack inside one word destroyed the
  dictionary).
- **Not fixed, with the reason:** LINE still takes byte coordinates; 16-bit line clipping rebuilds `GFX_LINE`, whose
  cells POLYGON also uses through the EXROM (ROADMAP: the display step).

## 3. Tests

attributes, HIRES attributes in the SCLD's layout, RAM outside the screen, the data stack, the paging depth) and a
speed table gated by `--compare`; run on the old build first (`docs/V2/evidence/t14_old_build.txt`: old 17/17, new
0/6). Every behaviour change has a case that fails without it: the noise and recolour-noise cases fail with
`FILL_SWEEP` disabled; `circle_hires`, `plot_hires`, `plot_offscreen`, `line_below_screen` and floattest's two new
checks fail on `c85c776`, the build before the defect fixes. cartdiff gained `fill_box`, `fill_recolour`,
`circle_clip`, `loop_shapes`. Smoke ROMs p44 and p65 (FILL only) are gone, p5/p17/p48/p55 lost their FILL/CIRCLE
steps, `test_shapes` carries the rest until the test step replaces the test ROMs.
